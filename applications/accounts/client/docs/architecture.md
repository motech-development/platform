# Accounts client architecture

## Purpose

`@accounts/client` is the Accounts web application: a React single-page app built with Vite that users sign in to with Auth0 to manage companies, clients, transactions, settings and reports. It talks to [`@accounts/api`](../../api/) over GraphQL (AppSync) and uses presigned S3 URLs from the API for attachments and reports. It is installable as a PWA. It owns no CloudFormation stack; its build is uploaded to the bucket created by [`@accounts/infrastructure`](../../infrastructure/). The newer [`@accounts/web`](../../web/) workspace is a placeholder for its replacement. See the [repository architecture](../../../../docs/architecture.md) for the wider picture.

## Start-up

`src/index.tsx`:

1. Initialises Sentry (`@sentry/react`) with React Router tracing and session replay. It is enabled only when `NODE_ENV` is `production`; its environment is `STAGE`.
2. Initialises Google Analytics (`react-ga`) and sends Web Vitals through `@motech-development/ga-web-vitals`.
3. Renders `BrowserRouter` → `Auth0Provider` (refresh tokens, `localstorage` cache, redirect back to `appState.returnTo`) → Breeze UI base styles and toast provider → `App`.
4. Registers the service worker; on update it calls `registration.update()`.

`invariant` throws at start-up if `REACT_APP_SENTRY_DSN`, `REACT_APP_GA` or any Auth0 variable is missing.

`App` wraps pages in `WithAuth` from `@motech-development/auth`, shows a toast and logs out on an auth error, and logs out after inactivity: 10 minutes in production, 60 minutes otherwise.

Everything under `/my-companies/*` is a `ProtectedRoute` and is wrapped in the `ApolloClient` component and a `UserBar`. The user bar's `UserNotifications` uses `GetNotifications`, `MarkAsRead` and the `OnNotification` subscription.

### Attachments and reports

- **Upload** (`Accounts/shared/UploadAttachment`): `RequestUpload` returns a presigned URL; the file is `PUT` to it with `usePut` from `@motech-development/axios-hooks`, and the form's `attachment` field is set to `<companyId>/<upload id>.<extension>`.
- **Download** (`Accounts/shared/ViewAttachment`): `RequestDownload` returns a presigned URL; the file is fetched with `useLazyGet` and saved with `file-saver`. `DeleteFile` removes it.
- **Reports** (`Reports/Reports`): lists reports with `createdAt`, `downloadUrl` and `ttl`, downloads the ZIP with `useLazyGet` and saves it as `report.zip`.

Notification messages such as `REPORT_READY_TO_DOWNLOAD` and `VIRUS_SCAN_FAIL` are translation keys in `src/locales/en/user-notifications.json`.

## Apollo client

`src/components/ApolloClient.tsx` renders `Apollo` from `@motech-development/appsync-apollo`, which connects to AppSync with `REACT_APP_APPSYNC_URL` and `REACT_APP_AWS_REGION` and authenticates with Auth0's `getAccessTokenSilently`. It shows a loader while Auth0 loads and translated error cards on error or when unauthorised.

Cache type policies:

| Policy                        | Behaviour                                                                                                                                                                                                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Mutation.deleteTransaction`  | Removes the transaction from the matching `Transactions` list (keyed by `companyId` and `status`) and from `Balance.transactions`, then evicts it and runs `cache.gc()`.                                                                                                                   |
| `Query.getNotifications`      | Replaces with the incoming result.                                                                                                                                                                                                                                                         |
| `Subscription.onNotification` | Writes the notification to the cache and prepends it to `getNotifications` lists. If its `payload` parses (as JSON, or as a query string with `id`, `createdAt`, `downloadUrl`, `ttl`) to a report, also writes the `Report` and appends it to `getReports` lists. Duplicates are ignored. |
| `Transactions`                | Key fields `id` and `status`. `items` merges incoming with existing without duplicates and drops dangling references on read.                                                                                                                                                              |

## i18n

`src/i18n.ts` uses i18next with browser language detection, fallback `en` and default namespace `global`. Other namespaces are loaded on demand by dynamic import of `src/locales/<language>/<namespace>.json`, so each JSON file is its own chunk. Debug logging is on outside production.

## Service worker and PWA

`vite-plugin-pwa` builds `src/service-worker.ts` with the `injectManifest` strategy and `autoUpdate` registration. The worker:

- claims clients immediately and initialises Workbox offline Google Analytics;
- precaches the build manifest and serves navigation requests (except paths starting `/_` or with a file extension) from `/index.html`;
- uses network-first for `locales/*.json`, stale-while-revalidate for Google Fonts (20 entries) and avatar images (5 entries);
- skips waiting on a `SKIP_WAITING` message.

Registration happens only in production builds. Icons and splash screens in `public/` are generated from `assets/` by the `build-icons` and `build-splash:*` scripts.

## Build

`vite.config.mts`:

- outputs to `build/` with source maps; `base` is `PUBLIC_URL` (default `/`) and the port is `PORT` (default `3000`);
- runs ESLint and the TypeScript checker except in production builds;
- copies `pdfjs-dist` CMaps and standard fonts for the document viewer;
- uploads source maps with `@sentry/vite-plugin`, authenticated by `SENTRY_AUTH_TOKEN`.

### Environment variables

Read from the environment or a git-ignored `.env.local`. Never commit values.

| Variable                    | Required | Purpose                                 |
| --------------------------- | -------- | --------------------------------------- |
| `REACT_APP_AUTH0_DOMAIN`    | Yes      | Auth0 tenant domain.                    |
| `REACT_APP_AUTH0_CLIENT_ID` | Yes      | Auth0 application client ID.            |
| `REACT_APP_AUTH0_AUDIENCE`  | Yes      | Auth0 API audience.                     |
| `REACT_APP_APPSYNC_URL`     | Yes      | Accounts API GraphQL URL.               |
| `REACT_APP_AWS_REGION`      | Yes      | Accounts API region.                    |
| `REACT_APP_GA`              | Yes      | Google Analytics ID (checked at start). |
| `REACT_APP_SENTRY_DSN`      | Yes      | Sentry DSN (checked at start).          |
| `STAGE`                     | No       | Sentry environment.                     |
| `PORT`, `PUBLIC_URL`        | No       | Dev server port and base path.          |
| `SENTRY_AUTH_TOKEN`         | No       | Build-time source map upload.           |

## Deployment

Production only. The delivery workflow builds the client with the outputs of `@accounts/api` and runs `deploy`, which uses `serverless-finch` to upload `build/` to the `accounts.<PROD_DOMAIN>` bucket from `@accounts/infrastructure` (`manageResources: false`, so nothing is created). Cache headers: HTML and `service-worker.js` are `no-store`, `locales/**/*.json` `max-age=0`, `static/**/*.js` one year.

## Testing

### Unit tests

Vitest with jsdom. Tests live in `__tests__` folders next to the code (`src/**/__tests__/**/*.{ts,tsx}`), run serially with `mockReset` on and a 5-second timeout. `src/setupTests.ts` adds `jest-dom` matchers, mocks `useAuth0` and `file-saver`, and polyfills `matchMedia`, `crypto`, streams, `structuredClone` and `Promise.withResolvers`. `src/utils/TestProvider.tsx` wraps components with the providers they need. Workspace packages are aliased to their built `lib/` output in `vitest.config.ts`, so run `yarn package` first.

Run one file from the repository root:

```sh
yarn workspace @accounts/client exec vitest run src/components/__tests__/ApolloClient.tsx
```

### End-to-end tests

Playwright (`playwright.config.ts`, tests in `e2e/`). A `setup` project logs in through Auth0 with `E2E_USERNAME` and `E2E_PASSWORD` and saves the session to `playwright/.auth/user.json`; the `chromium` project reuses it. `vat-registered.spec.ts` and `non-vat-registered.spec.ts` walk through companies, settings, clients, transactions, attachments (including a virus-scan check that writes the EICAR test string to a fixture file), reports and notifications, with axe accessibility checks from `e2e/fixtures.ts`.

Set `BASE_URL` to test a deployed environment; otherwise Playwright runs `serve` (`vite preview`) on port 3000, so run `build` first. Outside CI, Playwright reuses any server already listening on port 3000, so stop the dev server when you need to test the build. Also outside CI, `.env` and `.env.local` are loaded. In CI, tests retry twice, use one worker per shard and run in two shards, against Preview Environments in the delivery workflow and against production on a schedule.

## Making changes

- After changing a GraphQL operation in a page, or the schema in `../api/schema/*.graphql`, run `yarn workspace @accounts/client codegen.graphql` to regenerate `src/graphql/`. Codegen reads operations from `src/**/*.tsx`.
- New translation namespaces go in `src/locales/en/<namespace>.json` and are loaded by name with `useTranslation('<namespace>')`.
- Notification `message` keys and report `payload` parsing must match what `@accounts/reports` and other senders write.
- Changing the bucket name derivation in `serverless.yml` must match `@accounts/infrastructure`.
