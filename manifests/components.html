# BreezeProvider

`BreezeProvider` provides the locale, appearance and styles that Breeze UI components require. Render it once, above every Breeze UI component. Components rendered without a provider throw an error.

```tsx
<BreezeProvider locale="en-GB">
  <Button>Save changes</Button>
</BreezeProvider>
```

<Canvas of={Stories.Default} />

## Locale

`locale` takes a BCP 47 language tag. It sets the `lang` attribute and the text direction of the provider's root element.

Only English (`en-GB`) messages are bundled. Supply partial `messages` to translate Breeze's loading announcement and appearance control into the provider locale. Without an override, Breeze's own text uses English and is marked `lang="en-GB"`, independently of the surrounding content's language.

```tsx
<BreezeProvider locale="fr-FR" messages={{ loading: 'Chargement' }}>
  <Button loading>Enregistrer</Button>
</BreezeProvider>
```

<Canvas of={Stories.Locale} />

## Appearance

Appearance defaults to `automatic`, which follows the operating system and keeps following it when the preference changes. The provider resolves the choice to `light` or `dark`, then applies that value and the matching `color-scheme` to the document element.

Use `defaultAppearance` when Breeze should hold the current choice in memory:

```tsx
<BreezeProvider
  defaultAppearance="automatic"
  locale="en-GB"
  onAppearanceChange={(appearance) => saveAppearance(appearance)}
>
  <App />
</BreezeProvider>
```

Use `appearance` with `onAppearanceChange` when application state controls it. `appearance` and `defaultAppearance` are mutually exclusive.

```tsx
<BreezeProvider
  appearance={appearance}
  locale="en-GB"
  onAppearanceChange={setAppearance}
>
  <App />
</BreezeProvider>
```

The provider never reads or writes durable browser storage. The application decides whether and where to persist the reported choice. If a persisted explicit choice must apply before the application starts, stamp its resolved value on the document element before loading the stylesheet; the stylesheet's media-query default already handles automatic dark mode before script runs.

# Button

Buttons let users perform an action, such as saving a record or submitting a form.

## Basic button

`Button` comes with four variants: `primary` (default), `secondary`, `quiet` and `danger`. The `children` prop sets the visible label.

<Canvas of={Stories.Primary} />

## Secondary button

Secondary buttons are neutral alternatives to the primary action, such as cancelling.

<Canvas of={Stories.Secondary} />

## Quiet button

Quiet buttons are low emphasis, for actions that sit alongside content.

<Canvas of={Stories.Quiet} />

## Danger button

Danger buttons are destructive actions. Use a label that states what will be removed.

<Canvas of={Stories.Danger} />

## Sizes

`size` accepts `sm`, `md` (default) and `lg`, with minimum heights of 34, 38 and 52px.

<Canvas of={Stories.TreatmentsAndSizes} />

Labels wrap and increase the height of the button:

<Canvas of={Stories.LongLabel} />

## Loading

Set `loading` while the action is in progress. The label is replaced by a skeleton, and the button cannot be activated again.

<Canvas of={Stories.Loading} />

## Disabled

`disabled` prevents activation and removes the button from the tab order.

<Canvas of={Stories.Disabled} />

## Handling actions

`onAction` is called when the button is activated, and takes no arguments.

<Canvas of={Stories.Activation} />

## Form submission

Use `type="submit"` to submit the containing form, and handle submission on the form. The default is `type="button"`. The `form`, `name` and `value` props are available for form association.

## Accessibility

The label provides the accessible name and is retained while the button is loading. Buttons receive a 44px minimum target on touch devices, and `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-expanded` and `aria-haspopup` are supported.

import '@motech-development/breeze-ui/styles.css';

import '@motech-development/breeze-ui/reset.css';

# Usage

Breeze UI components must be rendered inside `BreezeProvider`. Add it once, at the root of your application:

```tsx
import { BreezeProvider } from '@motech-development/breeze-ui';
import { createRoot } from 'react-dom/client';
import { App } from './App';
import '@motech-development/breeze-ui/styles.css';

const root = document.getElementById('root');

if (root) {
  createRoot(root).render(
    <BreezeProvider locale="en-GB">
      <App />
    </BreezeProvider>,
  );
}
```

Components can then be used anywhere below the provider:

```tsx
import { Button } from '@motech-development/breeze-ui';

export function SaveAction() {
  return <Button onAction={() => saveChanges()}>Save changes</Button>;
}
```

## Locale

`BreezeProvider` takes a BCP 47 language tag, such as `en-GB` or `fr-FR`. Components use it for accessible interactions and text direction.

## Appearance

Components follow the operating system colour scheme by default. Add `AppearanceControl` anywhere below the provider to let a person choose Light, Auto or Dark:

```tsx
import {
  AppearanceControl,
  type Appearance,
  BreezeProvider,
} from '@motech-development/breeze-ui';
import { useState } from 'react';

export function Root() {
  const [appearance, setAppearance] = useState<Appearance>('automatic');

  return (
    <BreezeProvider
      appearance={appearance}
      locale="en-GB"
      onAppearanceChange={setAppearance}
    >
      <AppearanceControl />
      <App />
    </BreezeProvider>
  );
}
```

The application owns persistence. Breeze reports changes and accepts an initial or controlled value, but never reads or writes browser storage.

## Customisation

Component appearance is set through the props documented on each component page. `className`, `style` and theme overrides are not supported.
