# BreezeProvider

`BreezeProvider` provides the locale, appearance and styles that Breeze UI components require. Render it once, above every Breeze UI component. Components rendered without a provider throw an error.

```tsx
<BreezeProvider locale="en-GB">
  <Button>Save changes</Button>
</BreezeProvider>
```

<Canvas of={Stories.Default} />

## Locale

`locale` takes a BCP 47 language tag. It sets the `lang` attribute and the text direction of the provider's root element.

Only English (`en-GB`) messages are bundled. Supply partial `messages` to translate Breeze's loading announcement, appearance control and overlay close button into the provider locale. Without an override, Breeze's own text uses English and is marked `lang="en-GB"`, independently of the surrounding content's language.

```tsx
<BreezeProvider locale="fr-FR" messages={{ loading: 'Chargement' }}>
  <Button loading>Enregistrer</Button>
</BreezeProvider>
```

<Canvas of={Stories.Locale} />

## Appearance

Appearance defaults to `automatic`, which follows the operating system and keeps following it when the preference changes. The provider resolves the choice to `light` or `dark`, then applies that value and the matching `color-scheme` to the document element.

Use `defaultAppearance` when Breeze should hold the current choice in memory:

```tsx
<BreezeProvider
  defaultAppearance="automatic"
  locale="en-GB"
  onAppearanceChange={(appearance) => saveAppearance(appearance)}
>
  <App />
</BreezeProvider>
```

Use `appearance` with `onAppearanceChange` when application state controls it. `appearance` and `defaultAppearance` are mutually exclusive.

```tsx
<BreezeProvider
  appearance={appearance}
  locale="en-GB"
  onAppearanceChange={setAppearance}
>
  <App />
</BreezeProvider>
```

The provider never reads or writes durable browser storage. The application decides whether and where to persist the reported choice. If a persisted explicit choice must apply before the application starts, stamp its resolved value on the document element before loading the stylesheet; the stylesheet's media-query default already handles automatic dark mode before script runs.

## Overlay portal

`Dialog`, `Drawer` and `Popover` render into a dedicated portal host owned by the provider. By default, the host is appended to `document.body`. Set `portalContainer` to an existing light DOM `HTMLElement` in the current runtime document when overlays need to render in another container, such as an embedded application or a test fixture.

```tsx
<BreezeProvider locale="en-GB" portalContainer={overlayContainer}>
  <App />
</BreezeProvider>
```

The provider creates and removes its own host inside that container. The host carries the Breeze root marker, locale and text direction so overlays retain scoped styling and language outside the provider's normal content tree.

`portalContainer` and every overlay trigger must belong to the current runtime `Document` and its light DOM. Cross-document and shadow-root portals are unsupported because React Aria positions and manages overlays against the runtime document.

## Confirmations

Use `useToast` below the provider to announce a completed action. The provider owns the status region, displays up to three messages at once and queues additional messages in FIFO order. Each message remains visible for 2.6 seconds after it becomes visible.

```tsx
import { useToast } from '@motech-development/breeze-ui';

function SaveAction() {
  const enqueue = useToast();

  return <Button onAction={() => enqueue('Changes saved')}>Save</Button>;
}
```

Set `toastLimit` when the application needs a different number of visible confirmations. Provider-enqueued confirmations stay 288px wide at every supported viewport, have no action or dismissal control, and expire after 2.6 seconds once visible.

# ComboBox

`ComboBox` combines text entry with a popover listbox. Suggestions filter while
the user types, and the same closed descriptor contract is used for every item.

<Canvas of={Stories.Default} />

## Descriptor content

Pass `items` and a `getItem` mapping function. The mapping returns only
`ItemDescriptor` data: `id`, `label`, optional `description`, `icon`, `badge` and
`disabled`. It cannot return JSX, classes, styles or slot props. A content gap is

# Popover

Use `Popover` for non-modal contextual content anchored to a trigger. The surrounding surface remains interactive and available to assistive technology; the popover has no dimmed scrim. Render it inside `BreezeProvider`.

## Basic usage

`trigger` supplies the label for the button Breeze renders. `title` supplies the surface's visible heading and accessible name; `children` supplies its content. Breeze also renders a close button with a label from the provider's messages.

```tsx
<Popover title="Delivery details" trigger="View delivery details">
  <Typography>Your delivery details appear here.</Typography>
</Popover>
```

<Canvas of={Stories.Default} />

## Open state

By default, the component manages its own open state. Set `defaultOpen` to start open, and optionally use `onOpenChange` to observe changes.

To control the surface from application state, supply both `open` and `onOpenChange`. `open` and `defaultOpen` are mutually exclusive.

```tsx
<Popover
  onOpenChange={setOpen}
  open={open}
  title="Delivery details"
  trigger="View delivery details"
>
  <Typography>Your delivery details appear here.</Typography>
</Popover>
```

## Dismissal

`dismissible` defaults to `true`, allowing Escape and interaction outside the surface to dismiss it. Set it to `false` when those interactions should leave the surface open. The close button remains available.

## Placement

`placement` accepts `top`, `bottom` (default), `start` or `end`. Start and end follow the provider's text direction. The surface can adjust its position to fit the available space.

## Accessibility and motion

Breeze manages focus on opening and restores it on closing without trapping focus inside the popover. The provider's portal host keeps the surface's locale, direction and scoped styles intact.

Inside a drawer, a popover appears above the sheet while its content remains interactive and accessible. The sheet keeps its scrim. Escape closes the popover first and restores focus to its trigger; a subsequent Escape closes the sheet. The `Foundations/Overlay stack` stories exercise this composition.

Enter and exit motion respects reduced-motion preferences. A closing surface immediately leaves the active stack while its exit animation completes.

# Breeze UI

Breeze UI is the React component library used to build Motech Development applications. Its components are accessible, keyboard navigable, and styled for light and dark colour schemes.

# Installation

Run the following command to add Breeze UI to your application:

```sh
yarn add @motech-development/breeze-ui
```

## Peer dependencies

`react` and `react-dom` are peer dependencies. Breeze UI requires React 19.

## Styles

Import the stylesheet once, at the entry point of your application:

```tsx
import '@motech-development/breeze-ui/styles.css';
```

## Reset

Breeze UI provides an optional reset for browser default styles. To use it, import it before the stylesheet:

```tsx
import '@motech-development/breeze-ui/reset.css';
import '@motech-development/breeze-ui/styles.css';
```

# Usage

Breeze UI components must be rendered inside `BreezeProvider`. Add it once, at the root of your application:

```tsx
import { BreezeProvider } from '@motech-development/breeze-ui';
import { createRoot } from 'react-dom/client';
import { App } from './App';
import '@motech-development/breeze-ui/styles.css';

const root = document.getElementById('root');

if (root) {
  createRoot(root).render(
    <BreezeProvider locale="en-GB">
      <App />
    </BreezeProvider>,
  );
}
```

Components can then be used anywhere below the provider:

```tsx
import { Button } from '@motech-development/breeze-ui';

export function SaveAction() {
  return <Button onAction={() => saveChanges()}>Save changes</Button>;
}
```

## Locale

`BreezeProvider` takes a BCP 47 language tag, such as `en-GB` or `fr-FR`. Components use it for accessible interactions and text direction.

## Appearance

Components follow the operating system colour scheme by default. Add `AppearanceControl` anywhere below the provider to let a person choose Light, Auto or Dark:

```tsx
import {
  AppearanceControl,
  type Appearance,
  BreezeProvider,
} from '@motech-development/breeze-ui';
import { useState } from 'react';

export function Root() {
  const [appearance, setAppearance] = useState<Appearance>('automatic');

  return (
    <BreezeProvider
      appearance={appearance}
      locale="en-GB"
      onAppearanceChange={setAppearance}
    >
      <AppearanceControl />
      <App />
    </BreezeProvider>
  );
}
```

The application owns persistence. Breeze reports changes and accepts an initial or controlled value, but never reads or writes browser storage.

## Customisation

Component appearance is set through the props documented on each component page. `className`, `style` and theme overrides are not supported.
