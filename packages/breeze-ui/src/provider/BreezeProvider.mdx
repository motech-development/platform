# BreezeProvider

`BreezeProvider` supplies the locale, appearance and messages that Breeze UI components need. Render it once, at the root of your application, above every Breeze UI component. A component rendered outside a provider throws an error.

```tsx
<BreezeProvider locale="en-GB">
  <Button>Save changes</Button>
</BreezeProvider>
```

## Locale

`locale` takes a BCP 47 language tag, such as `en-GB` or `fr-FR`. It sets the language and text direction of everything inside the provider, and the locale used to format numbers, amounts and dates.

### Translating messages

Breeze includes English (`en-GB`) text only. To translate it, pass a partial `messages` object; any key you leave out stays in English and is marked as English for screen readers, whatever the page language. Messages cover:

- loading and required-field announcements
- the `DatePicker` placeholder, Today and clear actions
- the `ComboBox` no-match message and the `RowList` empty message
- `AppearanceControl`
- the close button on overlays
- the `Popover` unread indicator
- `FileDropZone` instructions and feedback
- `DocumentViewer` controls and messages
- attachment labels and actions
- the `SkipLink` text and the `ApplicationShell` navigation label

Other built-in interaction labels are available in English only.

```tsx
<BreezeProvider
  locale="fr-FR"
  messages={{ loading: 'Chargement', selectDate: 'Sélectionner une date' }}
>
  <Button loading>Enregistrer</Button>
  <DatePicker label="Date" />
</BreezeProvider>
```

<Canvas of={Stories.Locale} />

Some messages contain placeholders that are replaced with values. Keep them in your translations:

- `{query}` in `comboBoxNoMatches` is the text the person typed.
- In the `FileDropZone` messages, `{types}` is the accepted file types, `{size}` the size limit, `{count}` the number of files added, `{current}` and `{max}` the attachment count and limit, `{fileName}` a rejected file, and `{fileNames}` the files rejected for exceeding the total limit.

For example:

```tsx
<BreezeProvider
  locale="fr-FR"
  messages={{
    fileDropZoneChooseFiles: 'Choisir des fichiers',
    fileDropZoneAddedMany: '{count} fichiers ajoutés.',
    fileDropZoneTypeRejected:
      '{fileName} : Type de fichier non accepté. Formats autorisés : {types}.',
    attachmentDocument: 'Document',
    attachmentPhoto: 'Photo',
    attachmentOpen: 'Ouvrir',
    attachmentMoreActions: 'Plus d’actions',
  }}
>
  <App />
</BreezeProvider>
```

## Time zone

`timeZone` takes an IANA time-zone name, such as `Europe/London`, used to format times of day. Without it, the browser's time zone is used. The provider throws a `RangeError` for a name the browser does not recognise.

**No component formats a time of day yet, so `timeZone` currently has no visible effect.**

```tsx
<BreezeProvider locale="en-GB" timeZone="Europe/London">
  <App />
</BreezeProvider>
```

`timeZone` does not affect calendar dates, such as `Typography` with `format="date"`. A calendar date names a day rather than a moment in time, so it always displays the day you pass.

## Appearance

Appearance can be `light`, `dark` or `automatic`. The default, `automatic`, follows the operating system's colour scheme, including when it changes while the page is open.

To let the provider manage the current choice, set `defaultAppearance`. Use `onAppearanceChange` to save the choice, for example when someone changes it with `AppearanceControl`:

```tsx
<BreezeProvider
  defaultAppearance="automatic"
  locale="en-GB"
  onAppearanceChange={(appearance) => saveAppearance(appearance)}
>
  <App />
</BreezeProvider>
```

To control appearance from your own state, pass both `appearance` and `onAppearanceChange`. `appearance` and `defaultAppearance` cannot be combined.

```tsx
<BreezeProvider
  appearance={appearance}
  locale="en-GB"
  onAppearanceChange={setAppearance}
>
  <App />
</BreezeProvider>
```

The provider does not save the choice. Store it wherever suits your application, such as local storage or a user profile, and pass it back on the next visit.

To apply a saved `light` or `dark` choice before your application's JavaScript runs, and so avoid a flash of the wrong colour scheme, set `data-theme="light"` or `data-theme="dark"` on the `<html>` element before the stylesheet loads. You do not need to do this for `automatic`: the stylesheet already follows the operating system before any script runs.

## Overlay portal

`Dialog`, `Drawer` and `Popover` render outside your component tree, in a container the provider adds to `document.body`. To render them somewhere else, such as inside an embedded application, set `portalContainer` to an existing `HTMLElement`.

```tsx
<BreezeProvider locale="en-GB" portalContainer={overlayContainer}>
  <App />
</BreezeProvider>
```

The provider adds its own element inside that container and removes it when it unmounts. Overlays keep the provider's styles, locale and text direction wherever they render.

`portalContainer` and every overlay trigger must be in the current document. Containers in another document, such as an iframe, or inside a shadow root are not supported.

## Client-side navigation

Set `router` when your application uses a client-side router. A `Link` to a same-origin page then calls `router.navigate` with the destination and the link's `transitionTypes`, instead of loading a new page. Your router performs the navigation and can use browser view transitions; see <a href="./?path=/docs/guides-04-motion--docs" target="_top">Motion</a>.

```tsx
<BreezeProvider locale="en-GB" router={router}>
  <App />
</BreezeProvider>
```

`transitionTypes` defaults to an empty list, so a `navigate` function that takes only the destination works unchanged. External links, downloads, links with another `target`, clicks with a modifier key and links containing a `#` fragment use normal browser navigation. See `Link` for details.

## Confirmations

Call `useToast` in a component below the provider to confirm a completed action. Up to three messages are shown at once; further messages wait and appear in the order they were sent. Each message stays on screen for 2.6 seconds.

```tsx
import { useToast } from '@motech-development/breeze-ui';

function SaveAction() {
  const enqueue = useToast();

  return <Button onAction={() => enqueue('Changes saved')}>Save</Button>;
}
```

Set `toastLimit` to change how many messages are shown at once. Toasts are 288px wide at every screen size and have no action or dismiss button. See `Toast` for details.
