# BreezeProvider

`BreezeProvider` provides the locale, appearance and styles that Breeze UI components require. Render it once, above every Breeze UI component. Components rendered without a provider throw an error.

```tsx
<BreezeProvider locale="en-GB">
  <Button>Save changes</Button>
</BreezeProvider>
```

## Locale

`locale` takes a BCP 47 language tag. It sets the `lang` attribute and the text direction of the provider's root element.

Only English (`en-GB`) messages are bundled. Supply partial `messages` to translate Breeze's loading and required announcements, the DatePicker placeholder, appearance control, overlay close button, FileDropZone instructions and feedback, and attachment labels and actions into the provider locale. Without an override, Breeze's own text uses English and is marked `lang="en-GB"`, independently of the surrounding content's language.

Built-in interaction labels are available in English only. `locale` still sets the provider language and direction and formats locale-aware values; use `messages` for the Breeze-owned strings listed above.

```tsx
<BreezeProvider
  locale="fr-FR"
  messages={{ loading: 'Chargement', selectDate: 'Sélectionner une date' }}
>
  <Button loading>Enregistrer</Button>
  <DatePicker label="Date" />
</BreezeProvider>
```

<Canvas of={Stories.Locale} />

FileDropZone message strings use flat keys. Keep their placeholders when
providing translations: `{types}` for accepted types, `{size}` for the size
limit, `{count}` for multiple added files, `{current}` and `{max}` for the
attachment count, `{fileName}` for a rejected file, and `{fileNames}` for files
rejected by the total count limit. For example:

```tsx
<BreezeProvider
  locale="fr-FR"
  messages={{
    fileDropZoneChooseFiles: 'Choisir des fichiers',
    fileDropZoneAddedMany: '{count} fichiers ajoutés.',
    fileDropZoneTypeRejected:
      '{fileName} : Type de fichier non accepté. Formats autorisés : {types}.',
    attachmentDocument: 'Document',
    attachmentPhoto: 'Photo',
    attachmentOpen: 'Ouvrir',
    attachmentMoreActions: 'Plus d’actions',
  }}
>
  <App />
</BreezeProvider>
```

## Time zone

`timeZone` takes an IANA time-zone name, such as `Europe/London`, reserved for formatting times of day. **No component formats a time of day yet, so today it has no visible effect**; it is validated and provided now so the API does not change when one does. Without it, times of day will use the runtime's time zone. The provider throws a `RangeError` for a name the runtime does not recognise.

```tsx
<BreezeProvider locale="en-GB" timeZone="Europe/London">
  <App />
</BreezeProvider>
```

`timeZone` is intentionally not applied to calendar dates. A calendar date, such as `Typography`'s `format="date"`, names a day rather than an instant, so Breeze formats it in UTC and the displayed day never shifts. Applying a western zone to a UTC-midnight date would display the previous day.

## Appearance

Appearance defaults to `automatic`, which follows the operating system and keeps following it when the preference changes. The provider resolves the choice to `light` or `dark`, then applies that value and the matching `color-scheme` to the document element.

Use `defaultAppearance` when Breeze should hold the current choice in memory:

```tsx
<BreezeProvider
  defaultAppearance="automatic"
  locale="en-GB"
  onAppearanceChange={(appearance) => saveAppearance(appearance)}
>
  <App />
</BreezeProvider>
```

Use `appearance` with `onAppearanceChange` when application state controls it. `appearance` and `defaultAppearance` are mutually exclusive.

```tsx
<BreezeProvider
  appearance={appearance}
  locale="en-GB"
  onAppearanceChange={setAppearance}
>
  <App />
</BreezeProvider>
```

The provider never reads or writes durable browser storage. The application decides whether and where to persist the reported choice. If a persisted explicit choice must apply before the application starts, stamp its resolved value on the document element before loading the stylesheet; the stylesheet's media-query default already handles automatic dark mode before script runs.

## Overlay portal

`Dialog`, `Drawer` and `Popover` render into a dedicated portal host owned by the provider. By default, the host is appended to `document.body`. Set `portalContainer` to an existing light DOM `HTMLElement` in the current runtime document when overlays need to render in another container, such as an embedded application or a test fixture.

```tsx
<BreezeProvider locale="en-GB" portalContainer={overlayContainer}>
  <App />
</BreezeProvider>
```

The provider creates and removes its own host inside that container. The host carries the Breeze root marker, locale and text direction so overlays retain scoped styling and language outside the provider's normal content tree.

`portalContainer` and every overlay trigger must belong to the current runtime `Document` and its light DOM. Cross-document and shadow-root portals are unsupported.

## Client-side navigation

Set `router` when the application has a same-document router. `Link` sends qualifying same-origin link activations to `router.navigate`, together with the link's `transitionTypes`. The router owns the route update and can opt into browser view transitions; see <a href="./?path=/docs/guides-04-motion--docs" target="_top">Motion</a>.

```tsx
<BreezeProvider locale="en-GB" router={router}>
  <App />
</BreezeProvider>
```

The `transitionTypes` option defaults to an empty list. A `navigate` function that accepts only `href` can ignore the second argument. External destinations, downloads, alternate targets, modified clicks and fragment links retain native anchor behavior.

## Confirmations

Use `useToast` below the provider to announce a completed action. The provider owns the status region, displays up to three messages at once and queues additional messages in FIFO order. Each message remains visible for 2.6 seconds after it becomes visible.

```tsx
import { useToast } from '@motech-development/breeze-ui';

function SaveAction() {
  const enqueue = useToast();

  return <Button onAction={() => enqueue('Changes saved')}>Save</Button>;
}
```

Set `toastLimit` when the application needs a different number of visible confirmations. Provider-enqueued confirmations stay 288px wide at every supported viewport, have no action or dismissal control, and expire after 2.6 seconds once visible.
