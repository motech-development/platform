# ApplicationShell

`ApplicationShell` is the frame around an application's pages. It renders a top bar, section navigation, a skip link and the main landmark, and adapts its navigation between desktop and mobile layouts.

## Navigation items

Pass your navigation data as `items`, and use `getItem` to map each item to the fields the shell needs:

- `id`: a stable identifier;
- `href`: the destination;
- `label`: the visible text;
- `icon` (optional): a Breeze `IconName`.

Set `currentItem` to the `id` of the current destination. That link is marked with `aria-current="page"`. In the top navigation it shows the navigation marker; in the bottom navigation its icon and label use the brand colour.

```tsx
<ApplicationShell
  account={<AccountMenu />}
  action={{ icon: 'add', label: 'Create item', onAction: createItem }}
  brand={<Brand />}
  context={<WorkspaceSwitcher />}
  currentItem={currentRoute.key}
  getItem={(route) => ({
    href: route.href,
    id: route.key,
    label: route.title,
  })}
  items={routes}
  notifications={<NotificationButton />}
>
  {pageContent}
</ApplicationShell>
```

Navigation items are regular links. When a router is configured on `BreezeProvider`, they navigate through it with `transitionTypes: ['nav']`.

## Slots

`brand`, `context`, `notifications` and `account` accept any React content. Give interactive content accessible names, especially icon-only controls. From the 901px breakpoint, a divider separates `brand` from `context`.

`children` is rendered inside the main landmark, stacked with a 16px gap.

## Primary action

`action` is required and renders as a circular, icon-only button:

- `icon` selects a Breeze icon;
- `label` is its accessible name;
- `onAction` is called when it is activated.

## Responsive layout

At 901px and wider, navigation sits horizontally beneath the top bar. When the links do not fit, the row scrolls horizontally and a focused link scrolls into view.

Below 901px, navigation becomes a 72px bar fixed to the bottom of the screen. The primary action is raised over the bar's top edge in a centre slot between the two halves of the items, and stays in place as the current page changes. The main content leaves room for the bar, the raised action and the device safe area.

## View transitions

The top bar, top navigation, bottom navigation and current-location marker take part in view transitions using Breeze UI's reserved shell roles. Render only one visible `ApplicationShell` at a time.

## Accessibility

- A skip link before the shell's chrome moves focus to the main landmark.
- The current destination is announced as the current page.
- On mobile, keyboard focus reaches the primary action between the two halves of the bottom navigation.
