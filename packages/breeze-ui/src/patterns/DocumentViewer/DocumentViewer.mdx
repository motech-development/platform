# DocumentViewer

`DocumentViewer` opens an attached image, PDF or other document in a full-screen preview with zoom, rotation and download controls. Use it to let people read an attachment without leaving the record it belongs to.

## Basic viewer

The viewer is controlled: pass `open` and `onOpenChange`, and render your own trigger, such as the Open button of an `AttachmentRow`. Set `src` to the file URL, `title` to the visible title, and `mediaType` to `image`, `pdf` or `document`.

## Toolbar

The toolbar shows the file name, the current zoom percentage and these actions:

- **Zoom** and **Rotate**, for images, PDF pages and embedded documents.
- **Download**, always available. `downloadName` sets the saved file name.
- **Full screen**, shown only when the browser supports the Fullscreen API.
- **Replace** and **Remove**, shown only when you pass `onReplace` or `onRemove`. Handle any confirmation in your application.

Multi-page PDFs add page navigation in a separate row beneath the toolbar. When you zoom a PDF, the current page stays visible and keeps its scroll position until the sharper version replaces it.

Downloads from another origin need the file host to allow CORS from your application, so the file name can be kept. If a download fails, for example because a presigned URL has expired, the viewer shows an error and stays open; it never navigates away to the file URL.

## PDFs

Images and other documents need no setup. PDFs are rendered page by page with selectable text using the optional `pdfjs-dist` peer dependency. Install a compatible version in your application:

```sh
yarn add pdfjs-dist@^6.2.108
```

PDF.js and its worker are loaded only when a PDF is opened, so they add nothing to your initial bundle. Together they are roughly 635 KiB gzipped.

The viewer fetches each PDF in a single request and makes no later byte-range requests, so a presigned URL only needs to be valid when the document is opened.

### Worker

By default, the viewer locates the PDF.js worker with `new URL('pdfjs-dist/build/pdf.worker.mjs', import.meta.url)`. Vite resolves this in production builds and emits the worker as an asset. For Vite's development server, exclude Breeze UI from dependency pre-bundling:

```ts
export default defineConfig({
  optimizeDeps: {
    exclude: ['@motech-development/breeze-ui'],
  },
});
```

With another bundler, or if you prefer not to change `optimizeDeps`, host the worker for your installed `pdfjs-dist` version and pass its URL as `pdfAssets.workerSrc`.

### Fonts and character maps

Some PDFs use predefined Adobe character maps or PDF.js standard fonts. To support them, copy the `cmaps/` and `standard_fonts/` directories from your installed `pdfjs-dist` version to public asset paths, and pass their URLs through `pdfAssets`:

```tsx
<DocumentViewer
  mediaType="pdf"
  onOpenChange={setOpen}
  open={open}
  pdfAssets={{
    cMapUrl: '/pdfjs/cmaps',
    standardFontDataUrl: '/pdfjs/standard_fonts',
  }}
  src={source}
  title="Quarterly report"
/>
```

The files must come from the same `pdfjs-dist` version. A trailing slash is added to each URL. Documents that do not use these assets work without them.

### Without PDF.js

If PDF.js is not installed or cannot render a file, the viewer shows the PDF in the browser's built-in PDF viewer instead. It fetches the file first, so the source must be same-origin or allow CORS. If the fetch fails, the viewer reports that the preview is unavailable and Download remains available.

When `pdfjs-dist` is not installed, Vite builds still succeed and use this fallback. Other bundlers may fail the build; install `pdfjs-dist`, or configure the bundler to ignore the missing optional module.

## Opening from an AttachmentRow

Give the `AttachmentRow` and the viewer the same unique `transitionName` to animate between the row and the viewer in both directions. The file is revealed once the opening animation finishes. Closing returns to the row, and any sheet or dialog around it stays open. Browsers without view transition support, and people who prefer reduced motion, see the same flow without animation.

## Accessibility

- `title` names the viewer.
- The viewer is non-modal. The page or sheet beneath it stays open and interactive, and remains available to assistive technology.
- While the viewer is open, Tab and Shift+Tab keep focus within its controls, and page scrolling is locked.
- Escape and the Close button close the viewer.
- Opened from a sheet, the viewer covers the screen while the sheet stays open behind it. Closing the viewer returns focus to the sheet, and closing the sheet also closes the viewer.

Rendered PDF pages are drawn as images, so screen readers cannot read their content. PDF text can be selected, but document tags, reading order and text in scanned images are not available. The viewer shows a notice to this effect and offers the original file for download, so make sure the surrounding record describes the attachment.

For `mediaType="document"`, the browser's own viewer displays the file, and its controls, keyboard support and accessibility vary by browser and file type. These frames are sandboxed, so embedded HTML or SVG cannot run scripts in your application.
