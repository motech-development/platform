# Accessibility and verification

Every Storybook story runs axe in Chromium, with violations treated as errors. The unit project uses jsdom and observes the public component contract. Coverage thresholds are 80%. Chromatic remains configured for visual reporting.

Breeze owns labels, styling, loading presentation, API translation and any hand-built interaction behavior. React Aria supplies the Button press, focus and pending behavior. An underlying kit is not evidence that every composition is accessible: the rendered Breeze stories still need their own checks.

This is Chromium-only browser coverage. Firefox and WebKit runs, RTL tests, manual screen-reader certification, a third-party accessibility audit and a VPAT are not claimed. Direction continues to be inferred from locale at runtime.

Button keeps its accessible name and occupied space while loading, has a visible keyboard focus outline, and enforces the automatic 44px coarse-pointer target floor. Its skeleton is static. Scoped reduced-motion rules protect future animations; document-global view-transition pseudo-elements will need a separate reduced-motion block because descendant selectors cannot reach them.
