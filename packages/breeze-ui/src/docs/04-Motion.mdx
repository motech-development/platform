# Motion

Breeze UI provides an opt-in helper for the browser's same-document View Transition API. Use a transition when it helps people follow how one state relates to the next.

Links do not animate on their own. Your router performs the route update and can wrap it in `startViewTransition` to animate it. The examples use stable React 19 and React DOM APIs, and no extra dependency is needed.

## Transition types

Choose the type that describes the change:

| Type     | Use it for                                                   |
| -------- | ------------------------------------------------------------ |
| `nav`    | Moving between sibling routes in the same application.       |
| `mode`   | Replacing a loading skeleton with its content.               |
| `list`   | Rearranging or filtering a collection of items.              |
| `item`   | Changing one item while the surrounding page stays in place. |
| `expand` | Expanding one item into a larger view of that same item.     |

The type decides which parts of the page can move. `nav` and `mode` may transition the whole page; `list`, `item` and `expand` leave the page in place and animate only the named participants.

Some updates should stay immediate:

- appearance changes, segmented-control state, typing and in-place recalculation, so input and the caret stay stable;
- form steps inside a sheet, where the sheet stays in place and the step indicator already shows progress.

## Declare a participant

Call `useViewTransitionParticipant` below `BreezeProvider` and attach its ref to the element that represents the same thing before and after the update. The element takes part only while one of its `types` is active.

```tsx
import { useViewTransitionParticipant } from '@motech-development/breeze-ui';

function TransactionRow({ transaction }) {
  const rowRef = useViewTransitionParticipant({
    name: `transaction-${transaction.id}`,
    types: ['list'],
  });

  return <li ref={rowRef}>{transaction.name}</li>;
}
```

Each `name` must start with a letter (A–Z or a–z) or an underscore, followed by letters, digits, underscores or hyphens. These names are reserved, in any letter case: `auto`, `default`, `inherit`, `initial`, `none`, `revert`, `revert-layer`, `unset`, `root`, `match-element`, `breeze-botnav`, `breeze-navmark`, `breeze-topbar` and `breeze-topnav`. An invalid or reserved name throws a `TypeError`.

Each `name` must also be unique among the visible participants before and after the update. In development, Breeze UI logs a console error for duplicate names.

While a dialog, drawer, menu or popover is open on top of the page, participants beneath it do not animate. A participant inside an overlay animates only when that overlay is the topmost one. A menu or popover stops counting as soon as it starts closing, so a navigation started from a menu item still animates the page; a closing dialog or drawer blocks transitions until its exit animation finishes.

### Application shell roles

Instead of a `name`, pass one of the reserved roles for your application's chrome:

```tsx
import { useViewTransitionParticipant } from '@motech-development/breeze-ui';

function TopBar() {
  const topbarRef = useViewTransitionParticipant({ role: 'topbar' });

  return <header ref={topbarRef}>Account</header>;
}
```

| Role      | Behaviour                                                      |
| --------- | -------------------------------------------------------------- |
| `topbar`  | Stays pinned during `nav` and `mode` transitions.              |
| `topnav`  | Stays pinned during `nav` and `mode` transitions.              |
| `botnav`  | Stays pinned during `nav` and `mode` transitions.              |
| `navmark` | Marks the current location and moves during `nav` transitions. |

Use each role on at most one visible element at a time. `ApplicationShell` already uses all four.

## Start a router transition

`Link` passes its `transitionTypes` to the `router.navigate` callback configured on `BreezeProvider`. Wrap the router's route update in `startViewTransition`:

```tsx
import { useState } from 'react';
import { flushSync } from 'react-dom';
import {
  BreezeProvider,
  Link,
  startViewTransition,
  type RouterNavigationOptions,
} from '@motech-development/breeze-ui';

function AppRouter() {
  const [path, setPath] = useState('/');
  const navigate = (
    href: string,
    { transitionTypes }: RouterNavigationOptions,
  ) =>
    startViewTransition(() => {
      flushSync(() => setPath(href));
    }, transitionTypes);

  return (
    <BreezeProvider locale="en-GB" router={{ navigate }}>
      <nav>
        <Link href="/" transitionTypes={['nav']}>
          Home
        </Link>
        <Link href="/transactions" transitionTypes={['nav', 'list']}>
          Transactions
        </Link>
      </nav>
      <main>{path === '/' ? <HomePage /> : <TransactionsPage />}</main>
    </BreezeProvider>
  );
}

function HomePage() {
  return <p>Home</p>;
}

function TransactionsPage() {
  return <p>Transactions</p>;
}
```

The update callback must not settle until the new page is in the DOM:

- For a synchronous React state update, wrap it in `flushSync`, as above.
- For asynchronous routing, wait for the router to signal that the new route has rendered. Finishing a data fetch or scheduling a state update is not enough.
- If the destination suspends, make sure the callback does not settle while a fallback is still showing.

`startViewTransition` returns a promise that resolves when the update completes and rejects if the update fails. The update still runs, without animation, when the type list is empty, the browser does not support typed view transitions, or the person prefers reduced motion. If a transition is already running, it is skipped before the next one starts.

## Overlays and toasts

Dialogs, drawers, menus, popovers and toasts have their own open and close animations. Do not wrap their opening or closing in `startViewTransition`.

## Browser reference

Read [Document.startViewTransition()](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition) and [Using view transition types](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using_types) for the browser API.
