# Button

Use `Button` to perform an action or submit a form. Its visible label describes the action.

```tsx
import { BreezeProvider, Button } from '@motech-development/breeze-ui';

<BreezeProvider locale="en-GB">
  <Button onAction={() => saveChanges()}>Save changes</Button>
</BreezeProvider>;
```

## Treatments and sizes

`variant` is one flat choice: `primary` for the principal action, `secondary` for a neutral alternative, `quiet` for low emphasis, or `danger` for destruction. Prefer one primary action per decision group. Colour never replaces a useful label.

`size` is `sm`, `md` (default), or `lg`: minimum block sizes of 34, 38 and 52px. Coarse pointers automatically receive a 44px minimum in both dimensions. Labels may wrap and increase the height; these are minimums, not clipping constraints.

## Loading and disabled

`loading` replaces the visible label with the button's own static skeleton. The label still determines the width and accessible name. React Aria prevents repeat activation, retains focusability, and announces the pending state; Breeze also exposes `aria-busy`. A static skeleton avoids unrelated motion and needs no reduced-motion alternative.

`disabled` prevents activation and removes the button from the tab order. Explain unavailable actions in nearby content when necessary.

## Forms and callbacks

`onAction` reports a semantic activation with no DOM event. For a form, use `type="submit"` and handle submission on the form. The default `type="button"` is safe inside forms. The native `form`, `name` and string `value` props support form association and submission.

Use `ref` for imperative focus where the surrounding interaction requires it. `id`, `aria-label`, `aria-labelledby`, `aria-describedby` and `aria-controls` are available for accessible relationships.

## Closed styling

There is no `className`, `style`, `slot`, render prop, icon slot or arbitrary attribute/event passthrough. `children` is the visible string label. Layout belongs to the parent; a missing visual treatment requires a library change. Version 3's separate `appearance` axis is gone.

## Accessibility

Breeze requires `BreezeProvider`. React Aria supplies press, keyboard and pending semantics; Breeze owns the rendered label, skeleton, target sizing and focus styling. Storybook runs axe in Chromium on every story. This is automated coverage, not a screen-reader certification, third-party audit or VPAT. Firefox, WebKit and RTL are not claimed test targets.
