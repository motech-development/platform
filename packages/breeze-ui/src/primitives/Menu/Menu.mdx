# Menu

`Menu` keeps related actions together under a labelled button. Use it for
secondary actions, such as account settings, that should stay out of the main
page until needed.

When the visible trigger label is shared by several controls, set
`triggerAriaLabel` to give each button a distinct accessible name while keeping
the visible label concise.

<Canvas of={Stories.Default} />

## Icon-only trigger

Omit `trigger` and set `triggerIcon` and `triggerAriaLabel` together for a
compact icon-only trigger, such as a More actions button. `triggerAriaLabel`
is then required, because it is the trigger's only name.

<Canvas of={Stories.IconOnlyTrigger} />

## Loading the menu

Use `loading` when the trigger should wait before opening. It shows a loading
bar while keeping its size and accessible label; an icon-only trigger replaces
its icon with a skeleton, as `IconButton` does. Actions in an already-open menu
remain available.

<Canvas of={Stories.Loading} />

## Define actions

Pass your application values in `items`. Use `getItem` to provide each value's
`MenuItemDescriptor`: `id` and `label` are required, while `description`,
`icon` or `initials`, `badge`, `disabled` and `section` are optional. Give each item a unique `id` within the
menu. Keep labels concise; use descriptions for a short explanation and icons
when they help people scan the choices.

## Group actions into sections

Give items a `section` to group them. Items sharing a section `id` are shown
together where the first of them appears, and dividers separate each section
from its neighbours. A section `label` shows as a header and names the group
for assistive technology; omit it to divide a group without a header.

Set `initials` instead of `icon` to show a short code, such as a company's
initials, in a brand tile before the label. The tile is decorative, so the label
must still identify the item.

<Canvas of={Stories.Sections} />

## Menu width

The open menu fits its items and is never narrower than its trigger. `width`
sets its minimum width: `md`, the default, is 256px and suits a list of names
such as a company switcher; `sm` is 208px and suits a short list of actions,
such as the file actions in `AttachmentRow`.

<Canvas of={Stories.NarrowWidth} />

## Panels that are not menus

A menu contains only actions, optionally grouped into labelled sections. Do not
use `Menu` for a panel that also shows information people read but cannot act
on, places controls inside a row or header, or offers a toggle group. Assistive
technology presents a menu as its menu items alone, so plain-text rows are
skipped, and the menu's arrow keys cannot reach a button placed inside an item
or a section header.

An account panel that lists notifications, gives one of them a Download action,
offers Mark all as read and an `AppearanceControl`, and then links to settings
is such a panel. Build it as a `Popover` with application content instead.

## Respond to a selection

`onAction` receives the selected application item from `items`, as
`Select`, `ComboBox` and `ToggleGroup` do. The menu closes when an action is
selected. Show that action's progress, confirmation or errors in
the page or dialog that follows.

Use `defaultOpen` when the menu manages its own visibility. To control
visibility, provide `open` and `onOpenChange` together.

<Canvas of={Stories.Controlled} />

## Keyboard use

Open the menu with the trigger button, Enter, Space or ArrowDown. Use the arrow
keys to move through enabled actions; type a label to jump to a matching action.
Enter or Space selects the focused action. Escape closes the menu and returns
focus to its trigger.
