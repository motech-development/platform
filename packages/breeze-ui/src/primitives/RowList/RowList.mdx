# RowList

`RowList` displays data as a list of rows, such as transactions or reports.
Each row is either an action itself or a static row with its own trailing
action. Each row has a leading label, optional metadata and
a trailing value, aligned in columns across the list.

<Canvas of={Stories.Default} />

## Row content

Pass your data as `items` and a `getItem` function that returns a
`RowListItemDescriptor` for each item:

- `id` and `label` are required. Keep each `id` unique and stable, so the
  focused row stays in place when the data changes.
- `description`, `icon`, `badge` and `disabled` are optional. `badge` takes a
  list to show several badges in order, such as “No receipt” and a scheduled
  date. Badges never wrap or shrink; the label truncates instead.
- `initials` shows short initials, such as a client's or company's, in a brand
  tile in place of `icon`. Set one or the other.
- `metadata` takes text or an ISO calendar date, or a list of them for several
  columns. Each column is 120px wide; set an entry's `width` to `md` (176px)
  or `lg` (240px) for longer text such as an email address. A column takes the
  widest `width` any row gives it.
- `narrowDescription` replaces `description` below the `md` breakpoint, where
  the metadata columns are hidden, so you can keep their content on phones.
- `value` takes text or a currency amount, formatted in the provider's locale.
  A currency `value` is formatted by `Typography`, so a non-finite amount or a
  malformed currency code throws a `RangeError` when the row is displayed.
- `metadataAmount` adds a second, muted currency column, such as VAT, between
  the metadata and the value. It is formatted like a currency `value`, without
  `tone`.

A metadata or value column takes up space only when at least one row in the
list uses it; otherwise the label extends into that space.

## Sections

Give rows a `section` object to group them under section headers. Keep each
section `id` stable when rows are added or merged.

Set the section's optional `summary` to show content at the end of its header.
The summary is read from the first row in each section:

- A currency summary takes the same fields as a currency `value`, shown at the
  header's 12px size, plus a `label` that screen readers announce before the
  amount, such as “Confirmed daily total”. The list does not add up the amounts
  for you; pass the total with its `tone` and `sign`.
- A text summary shows a muted note instead, such as “Not in the balance yet”
  for a section without a total.

## Column headings

Pass `headings` to show a row of column headings above the list, as the
example above does. Give the leading column a `label`, and add `metadata`,
`metadataAmount`, `value` or `action` for the columns you want to name, with a
list for `metadata` when there are several metadata columns. Each heading uses
the same column as the rows, so it stays aligned at every width and hides below
the `md` breakpoint wherever its column does.

A heading appears only above a column that at least one row uses. The
headings are hidden while the list has no rows. They are plain text, not table
headers.

## Money in and out

Currency values use the compact `amount` role from `Typography`, in the
default text colour. For money in, set `tone: 'positive'` and `sign: 'always'`
to show an explicit `+`; negative amounts use a true minus sign. `sign` works as
it does in `Typography`.

Set a row's `direction` to `in` or `out` to colour its icon tile for money in
or out, and pair it with the `incoming` or `outgoing` icon. Without
`direction`, the tile is neutral. Colour is never the only signal: the sign and
icon also show the direction.

## Phone layout

Below the `md` breakpoint, the value stays at the end of the row, the metadata
columns are hidden, and a row's badges move under its description so the label
keeps the full width. Keep anything essential in the label, description or
value, or repeat the hidden metadata in a `narrowDescription`.

## Row actions

With `onAction`, each row is an action, not a selection: the list keeps no
selection state. Activating a row calls `onAction` with that row's item from
`items`.

<Canvas of={Stories.Merging} />

## Static rows

Omit `onAction` when the rows are not actions themselves, such as a list of
reports. `getItem` then returns a `RowListStaticItemDescriptor`, which has no
`value` or `disabled`, and can end in its own `action`:

- `{ label, onAction }` renders a button.
- `{ label, href, download }` renders a link, which can download a file. It
  navigates through the provider's router like `Link`.

Both use the small secondary button treatment, in a 120px column at the end
of the row. Name the column with `headings.action`. A static row's label wraps
instead of truncating.

<Canvas of={Stories.StaticRows} />

### Unread rows

Set `unread` on rows that have a read state, such as notifications. An unread
row shows a brand dot and a heavier label, and screen readers hear the
provider's “Unread” message before the label. A read row keeps the dot's
space, so labels stay aligned. Omit `unread` for rows without a read state.

<Canvas of={Stories.Unread} />

## Loading

Set `loading` while fetching the first page of data or refreshing it:

- An empty list shows three placeholder rows, and screen readers hear a single
  loading announcement.
- A list that already has rows keeps them, along with the focused row, while
  loading.

<Canvas of={Stories.InitialLoading} />

<Canvas of={Stories.RetainedLoading} />

To show that a single row is still loading, set `loading` in its
`RowListItemDescriptor`. Its metadata and value are replaced with placeholders,
while its label, description, icon, badge and action stay available. This
example also shows a busy Load more button.

<Canvas of={Stories.Loading} />

### Loading more rows

Pass `loadMore` with a `label`, `onAction` and optional `loading` when another
page of data is available. Add a `status` to say what is loaded beside the
button, such as “Showing 11 transactions”, as the first example on this page
does. When your data has no total, count what is loaded rather than writing
“N of M”. The button keeps its label while busy, and screen
readers hear the same loading announcement as the list, without the existing
rows being read again.

## Empty list

When loading finishes with no rows, the list shows the provider's “No items to
display.” message, and screen readers announce it.

<Canvas of={Stories.Empty} />

## Accessibility

Give the list an `aria-label`, which is required. The list is a single Tab
stop: use the up and down arrow keys to move between rows, and Enter to
activate the focused row. In a static row, the right arrow key moves to the
row's action. Screen readers announce loading and empty states once,
through a single status message.
