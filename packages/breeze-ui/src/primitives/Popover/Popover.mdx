# Popover

A popover shows contextual content next to the button that opens it. It is not modal: the rest of the page stays usable, and the page is not dimmed behind it.

Use `Popover` rather than `Menu` when the content mixes information with controls, such as a list of notifications with their own actions beside an `AppearanceControl`. A `Menu` holds only a list of actions.

## Basic popover

Pass `trigger` as the label of the button that opens the popover, `title` as its heading and `children` as its content. The popover includes a close button, labelled with the provider's messages.

```tsx
<Popover title="Delivery details" trigger="View delivery details">
  <Typography>Your delivery details appear here.</Typography>
</Popover>
```

## Open state

By default, the popover manages its own open state. Set `defaultOpen` to start open, and use `onOpenChange` to respond to changes.

To control the popover from your own state, pass both `open` and `onOpenChange`. `open` and `defaultOpen` cannot be combined.

```tsx
<Popover
  onOpenChange={setOpen}
  open={open}
  title="Delivery details"
  trigger="View delivery details"
>
  <Typography>Your delivery details appear here.</Typography>
</Popover>
```

## Dismissal

By default, pressing Escape or clicking outside the popover closes it. Set `dismissible={false}` to keep it open in those cases; the close button still works. A popover with `variant="panel"` has no close button, so it is always dismissible.

## Placement

`placement` accepts `top`, `bottom` (default), `start`, `end` or `bottom end`. Use `bottom end` to open below the button with their end edges aligned, for a button at the end of a bar. Start and end follow the provider's text direction, and the popover moves if needed to fit on screen.

## Panels

Set `variant="panel"` for content that makes its own purpose clear, such as an account panel of notifications and settings. A panel has no visible title or close button, but `title` still names it for screen readers.

A panel's content runs edge to edge with no padding. The panel is at least 336px wide and grows to fit its content; on narrow screens it spans the viewport, less 12px on each side. It closes with Escape or a click outside it.

### Initials and unread indicator

Set `triggerInitials` to open the popover from a circular button showing a person's initials. `trigger` then becomes the button's accessible name only, so describe what it opens.

Set `triggerIndicator` to add a dot to the button, for example for unread notifications. Screen readers announce the provider's unread-items message rather than the dot itself. If you know the count, include it in `trigger`, for example "Account and notifications, 2 unread".

```tsx
<Popover
  placement="bottom end"
  title="Account and notifications"
  trigger="Account and notifications, 2 unread"
  triggerIndicator
  triggerInitials="MG"
  variant="panel"
>
  {/* Notifications, AppearanceControl and account links */}
</Popover>
```

## Inside a drawer

A popover opened inside a `Drawer` appears above it, and the drawer stays interactive and keeps its dimmed backdrop. Escape closes the popover first and returns focus to its button; pressing Escape again closes the drawer. See the `Foundations/Overlay stack` stories for examples.

## Accessibility

Opening the popover moves focus into it, and closing it returns focus to the button. Focus is not trapped, so people can Tab out of the popover to the rest of the page. The popover keeps the provider's locale and text direction even though it renders outside your component tree.

The open and close animations respect the user's reduced-motion setting. As soon as a popover starts to close, the content beneath it becomes interactive again, without waiting for the animation to finish.
