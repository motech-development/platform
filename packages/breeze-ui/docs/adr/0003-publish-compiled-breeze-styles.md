# Publish compiled Breeze styles

Breeze UI uses Tailwind internally and publishes two compiled stylesheet entry points: the required `styles.css` provides fonts, semantic tokens and prefixed component styles, while the optional `reset.css`, imported first, normalizes content only within `[data-breeze-root]` without Tailwind Preflight or a global document baseline. Consumers do not scan Breeze sources or align Tailwind versions; semantic CSS variables and cascade layers provide the styling boundary, with token selection and `color-scheme` on the document element and component painting scoped to the provider root. Components expose a closed API with typed visual variants and intentional native attributes, without `className`, `style`, slot or render passthrough; application-owned wrappers handle placement so consumers cannot accidentally override component styling or interaction structure.
